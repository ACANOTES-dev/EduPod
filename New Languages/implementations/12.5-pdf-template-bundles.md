# Implementation 12.5 — PDF Template Bundles

> **Phase:** 5.5 — PDF Architecture
> **Wave:** 12.5 (serial — must land after 12 and before 13 polish/cleanup)
> **Depends on:** 12 complete & deployed
> **Deploys:** API restart
> **Model:** GPT-5.5 / Max effort

---

## Goal

Replace the interim PDF locale path with a first-class template registry where each supported PDF locale owns a complete bundle of the 13 PDF templates.

This is **not** a language-pack implementation and it is **not** a normal web-message translation pass. The deliverable is a PDF architecture cleanup: every PDF template route resolves through a registered per-locale template bundle, and missing template keys or locales fail hard instead of drifting through a partial fallback.

Supported PDF locales at this gate:

- `en`
- `ar`
- `fr`
- `es`
- `de`
- `ga`
- `it`
- `ro`

## Critical safety constraints

- Preserve current English and Arabic PDF output contracts, including Arabic RTL layout.
- Preserve tenant-stored names, school names, addresses, student names, staff names, and user-entered data.
- Do not implement a new user-facing locale in this pass.
- Do not add `pl` PDF support before implementation 13 has been re-scoped and explicitly lands it.
- Do not change production `.env`, credentials, or secrets.
- Deploy only via `git push origin main` and GitHub Actions.
