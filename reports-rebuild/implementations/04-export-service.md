# Implementation 04 — Export Service (PDF / Excel / Word)

> **Wave:** 2 (parallel, API restart)
> **Depends on:** 01
> **Deploys:** API restart only

---

## Goal

Replace the current `ReportExportService` (`apps/api/src/modules/reports/report-export.service.ts`) with a unified export pipeline that produces branded PDF, rich Excel, and native Word documents from a single `{ rows, columns, meta }` input. Word is new; PDF and Excel are upgraded.

Every saved report, every scheduled report, every shared report, and every on-demand export funnels through this service. One pipeline, three renderers.

## What to change

### 1. Add dependencies

```bash
pnpm --filter @school/api add exceljs docx
# Puppeteer is already installed for report cards
```

Remove the `xlsx` dependency from the API package (it stays in the worker if anything else uses it; otherwise remove globally).

### 2. Service rewrite

New file layout under `apps/api/src/modules/reports/exports/`:

```
exports/
├── report-export.service.ts               # public entry
├── renderers/
│   ├── pdf-renderer.ts                    # Puppeteer
│   ├── excel-renderer.ts                  # exceljs
│   └── word-renderer.ts                   # docx
├── templates/
│   ├── pdf-report.html.ts                 # parametrised HTML template
│   └── branding.ts                        # header/footer/colour tokens per tenant
└── report-export.service.spec.ts
```

Public interface:

```ts
type ExportInput = {
  tenantId: string;
  report: {
    name: string;
    description?: string;
    filters_summary: string; // human-readable filter description
    generated_by: string; // user display name
    generated_at: Date;
  };
  data: {
    columns: Array<{
      id: string;
      label: string;
      type: 'string' | 'number' | 'date' | 'boolean' | 'currency';
    }>;
    rows: Record<string, unknown>[];
  };
  branding: TenantBranding; // logo_url, primary_colour, school_name
};

class ReportExportService {
  async exportPdf(input: ExportInput): Promise<Buffer>;
  async exportExcel(input: ExportInput): Promise<Buffer>;
  async exportWord(input: ExportInput): Promise<Buffer>;
}
```

### 3. PDF renderer

One branded HTML template parametrised per tenant:

- **Header** — tenant logo (from tenant settings), school name, "Report: {name}", generated-at timestamp.
- **Filters summary block** — "Filters applied: {filters_summary}".
- **Table** — styled, striped rows, column-type-aware formatting (dates as `dd/mm/yyyy`, currency with tenant symbol, booleans as ✓/✗).
- **Footer** — page N of M, "Confidential — generated for internal use" line.
- **Direction** — `dir="rtl"` if tenant's default locale is `ar`.
- **Orientation** — portrait default; landscape when `columns.length > 6`.

Render pipeline: build HTML → Puppeteer launches headless Chromium → `page.pdf({ format: 'A4', printBackground: true, margin: ... })` → return Buffer.

Reuse the existing Puppeteer launcher (check `apps/api/src/modules/report-cards/` for the pattern — one shared browser instance, page-per-render).

### 4. Excel renderer (`exceljs`)

Per-file:

- **Sheet 1: "Info"** — rows: Report name / Description / Generated at / Generated by / Filters applied.
- **Sheet 2: "Data"** — column headers frozen, column widths auto, number/date/currency formatted, booleans as TRUE/FALSE strings.
- **Styling** — primary colour from tenant branding on header row, alternate-row subtle fill, border on header.
- **Autofilter** enabled on the Data sheet header row.
- **Merged cells** on Info sheet where appropriate.

### 5. Word renderer (`docx`)

Per-file:

- **Page 1 header** — tenant logo image + school name + "Report: {name}" + generated timestamp.
- **Intro paragraph** — description (if any) + filters summary.
- **Table** — native Word table using `docx` `Table` + `TableRow` + `TableCell`. Type-aware cell text. Header row styled.
- **Footer** — page number + confidentiality notice.
- **Paragraph direction** — right-to-left if tenant locale is `ar` via `docx` bidirectional flag.

Known constraint: `docx` doesn't natively render Recharts charts. For v1 of Word export, **tables only**. If the report has a chart view in the builder, render the tabular data that feeds the chart (not the chart itself). A later cycle can snapshot the chart as an image via Puppeteer and embed it.

### 6. Tenant branding lookup

New helper `getTenantBranding(tenantId): Promise<TenantBranding>`. Reads `tenant.primary_colour_hex`, `tenant.logo_object_key` (existing fields), resolves to the full branding struct. Cache per tenant for 10 minutes in memory (the branding rarely changes).

If tenant has no branding set, fall back to the EduPod platform defaults.

### 7. On-demand HTTP endpoint

New endpoint `POST /v1/reports/builder/:id/export`:

```
POST body: { format: 'pdf' | 'excel' | 'word' }
```

Behaviour:

- Load saved report → execute via query engine → call export service → stream Buffer to client with appropriate `Content-Type` and `Content-Disposition`.
- If the query would return > 5 000 rows, return 202 Accepted with a job id and enqueue `reports:export-batch` — client polls or subscribes.
- Guard with `@RequiresPermission('reports.view')`.

### 8. Batch export worker hook

Add a stub processor file `apps/worker/src/processors/reports/reports-export-batch.processor.ts` that imports the service and processes the job. The full implementation (inbox delivery of the artifact) lives here — this phase ships the worker wiring end-to-end so impl 13 (sharing) reuses it directly. Register the queue + processor in the worker module.

The job payload: `{ tenant_id, user_id, saved_report_id, format, delivery: { email?: string[]; inbox_user_ids?: string[] } }`.

### 9. Delete legacy code

- `apps/api/src/modules/reports/report-export.service.ts` — delete (replaced by `exports/report-export.service.ts`).
- The dynamic `require('xlsx')` pattern — gone.
- The empty-buffer fallback — gone. Errors bubble up.

Update `ReportsModule` imports to use the new path.

## Testing requirements

- **Unit tests per renderer** — feed the same fixture ExportInput, assert the Buffer has the expected MIME signature (PDF: `%PDF-`, Excel: PK zip header, Word: PK zip header), assert size > 1 KB (not empty-fallback).
- **Integration test** — POST `/v1/reports/builder/:id/export?format=pdf` returns 200 with correct content-type and a parseable PDF.
- **Arabic-locale test** — export PDF for a tenant with locale `ar`, confirm RTL rendering (visual inspection in dev, snapshot test for HTML structure).
- **Large-export test** — seed > 5 000 rows, call export, confirm 202 Accepted with job id, confirm worker picks it up.

## Post-deploy verification

1. `POST /v1/reports/builder/:id/export` with `{ format: 'pdf' }` against a saved Student report — download and open in a PDF viewer. Header has NHQS logo, footer has page numbers, data table renders.
2. Same with `{ format: 'excel' }` — opens in Excel; Info sheet has metadata; Data sheet formatted; dates render as dates not numbers.
3. Same with `{ format: 'word' }` — opens in Word/Pages; table renders; metadata visible.
4. Arabic tenant test: switch a tenant's default locale to `ar`, export — text direction RTL.
5. Logs show no "xlsx missing, returning empty buffer" warnings.
