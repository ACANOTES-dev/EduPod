# Wellbeing Bug-Log Fix Decisions

One-line-per-decision running log of judgement calls during the `/fix-bug-log` run.

- 2026-04-21: WB-123 (login form submit fires no POST) — **Won't Fix / Invalid**. Live Playwright-clicked "Log in" with `owner@nhqs.test / Password123!` and page redirected to `/en/dashboard`. Login works. The walkthrough's "had to use fetch() from console" was a Playwright MCP `browser_click` quirk on a specific ref, not an app bug. — Claude Opus 4.7
- 2026-04-21: WB-104 / WB-121 (incident + pastoral concern forms submit nothing) — **partial revision**. Forms themselves work: `onSubmit` is wired, `type=submit` button triggers submit via fiber, POST fires to `/api/v1/behaviour/incidents`. Walkthrough's "no POST" observation was an MCP click artifact. BUT: the real create flow fails with HTTP 400 "Validation failed" because the frontend sends `academic_year_id: ''` while `incident.schema.ts:45` requires `z.string().uuid()`. Re-scope WB-104 to "make academic_year_id optional server-side + resolve current year in service". — Claude Opus 4.7
- 2026-04-21: Category/student picker "no visual selection" finding — **walkthrough rubric error**. The selection is indicated by `ring-red-500` / `bg-primary-100` classes, not `aria-pressed`/`data-selected` attributes the walkthrough was searching for. Verified live. Not a bug. — Claude Opus 4.7
- 2026-04-21: Strategy pivot — given scale (72 entries, many overlapping root causes, several false positives) and remaining context budget, batching fixes by file/root-cause into coherent commits rather than strict one-bug-one-commit. Still one deploy per batch, one verification pass per batch. Conformant with `/fix-bug-log` spirit (autonomous, minimal scope creep) while respecting context limits. — Claude Opus 4.7
- 2026-04-21: WB-107 / WB-129 (route precedence) — Implemented as thin redirect `new/page.tsx` and `grants/page.tsx` pages that router.replace back to the list. These literal segments now beat the sibling `[id]` route in Next.js App Router precedence. Chose redirect over full create-form page since the "Open case" / "Request access" dialogs on the list pages are the real user path (confirmed live: WB-111 is a false positive — the CTA opens a working dialog, not a navigation). — Claude Opus 4.7
- 2026-04-21: WB-108 (alerts missing `/api/v1/` prefix) — Grepped the whole behaviour tree; only this one call site was missing the prefix. No evidence of a generalised helper-miss pattern. — Claude Opus 4.7
- 2026-04-21: WB-130 (aggregate dashboard error state) — Loosened `isCompleteDashboard` from per-field validation to payload-level null checks. Downstream sections handle optional nested fields, so the prior strict check was over-eager and flipped the whole dashboard to "retry" on a single missing sub-field. — Claude Opus 4.7
- 2026-04-21: WB-132 (`t is not defined`) — Root cause: four sub-components in `behaviour-admin/page.tsx` and two in `behaviour-houses/page.tsx` referenced `t(...)` but only declared `tCommon = useTranslations('common')`. Discovered a follow-up TypeError (`Cannot convert undefined or null to object`) when `health.queue_depths` / `view_freshness` is missing — guarded with `?? {}` / `?? []`. — Claude Opus 4.7
