- 2026-04-21: Group 3 — WB-C-03 cross-instance AI-flag cache invalidation via Redis pub/sub on channel `ai-flags:invalidated`. Decision: use Redis pub/sub directly via the existing `RedisService` (ioredis client + duplicate connection for the subscriber side) rather than BullMQ — BullMQ jobs go to the worker, but every API instance needs to receive the invalidation. Failure modes are best-effort (subscribe error on boot is logged + swallowed; publish error on setFlag is logged + swallowed); the 5-min cache TTL bounds staleness even when pub/sub is unavailable. Local cache is also still cleared synchronously inside `setFlag` so the originating instance is consistent immediately. 5 new tests cover subscribe-on-init, publish-on-setFlag, message-handler invalidates remote cache, malformed payload tolerance, and subscribe-failure boot tolerance. Live verification: `redis pubsub CHANNELS '*'` lists `ai-flags:invalidated`, `NUMSUB` returns 1, PATCH `/v1/ai-flags/behaviour` returned 200. — Claude Opus 4.7
